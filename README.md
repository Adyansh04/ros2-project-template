# ROS 2 Project Development Template (updated)

This repository provides a lightweight, reproducible containerized ROS 2 development environment tuned for VS Code, clangd, and common robotics workflows.

Key changes in this template (recent updates)
- Host mounts: `./data` and `./workspaces` are the only project folders mounted into the container. Put your ROS workspaces under `workspaces/` (e.g. `workspaces/ros2_ws/src`).
- Workspace path in-container: the devcontainer and runtime workspace root is `/root/workspaces/ros2_ws`.
- `.vscode` handling: `manage.sh` will copy the repo `.vscode` into host workspaces (into `workspaces/ros2_ws/src/.vscode` and `workspaces/colcon_ws/src/.vscode`) if the destination doesn't exist. This keeps editor settings available inside the container even when `workspaces/` is a bind mount.
- Parameterized ROS distro: set `ROS_DISTRO` (defaults to `humble`) to select image tags and container names. Container name is `ros_dev_${ROS_DISTRO}`.
- GPU support: modern Compose GPU enablement is used (`gpus: all`) — requires NVIDIA Container Toolkit on the host.
- Hardware access: `/dev` is mounted and the container runs with `privileged: true` + `network_mode: host` so GUI, USB, and other peripherals work as in a normal dev environment.

## Features

- Devcontainer + `docker-compose.yml` for VS Code Remote - Containers.
- Central `manage.sh` script that launches, rebuilds, and prepares host workspaces.
- Clangd + `compile_commands.json` support (generated by `colcon build`).
- GPU-aware configuration (NVIDIA toolkit required on host).

## Prerequisites

- Docker Engine & Docker Compose
- (Optional, for GPU) NVIDIA Container Toolkit
- Visual Studio Code
- VS Code Dev Containers extension

## Getting started

1. Clone the template and enter the directory:

```bash
git clone <your-template-repo-url>
cd ros2_project_template
```

2. Make the management script executable:

```bash
chmod +x manage.sh
```

3. (Optional) choose a ROS distro for the container. If you don't set it, `humble` is used:

```bash
export ROS_DISTRO=humble
```

4. Add your workspaces and packages on the host. The repo now mounts the `workspaces/` folder into the container, so create your workspace here. Example structure:

```
workspaces/
	ros2_ws/
		src/
			my_package/
	colcon_ws/
		src/
```

5. Start the container (this will copy `.vscode` into the workspaces if missing and then build / run the container):

```bash
./manage.sh start
```

Note: the start process runs `xhost +local:docker` automatically. You may be prompted for a password to allow X access.

### Open in VS Code

1. Open the repository folder in VS Code.
2. Click **Reopen in Container**. The devcontainer uses `docker-compose.yml` and will attach to the running `ros-dev` service.
3. VS Code will open the workspace at `/root/workspaces/ros2_ws` inside the container.

## Daily workflow

- Start: `./manage.sh start`
- Rebuild image and restart: `./manage.sh recreate`
- Stop: `./manage.sh stop`
- Attach shell: `./manage.sh exec`

Build inside the container using the provided task (or run manually):

```bash
# inside container
source /opt/ros/$ROS_DISTRO/setup.bash
colcon build --symlink-install --cmake-args -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
```

The project includes a VS Code task that runs `colcon build` and generates `compile_commands.json` used by `clangd`.

## Where files live (host ↔ container)

- Host `./workspaces` -> Container `/root/workspaces` (bind mount)
- Host `./data` -> Container `/data` (bind mount)
- X11 socket `/tmp/.X11-unix` is mounted to support GUI apps
- `/dev` is bind-mounted into the container to give access to hardware devices

## `.vscode` behavior

Because bind-mounting `workspaces/` overlays the image contents, the Dockerfile `COPY .vscode ...` is ineffective at runtime. To ensure editor settings are available inside the mounted workspace, `manage.sh` copies the repository `.vscode` into these host workspace folders on first run (if the destination doesn't exist). You can always override or edit the workspace-local `.vscode` directly.

## GPU and GUI notes

- GPU: Compose uses `gpus: all`. Install the NVIDIA Container Toolkit on the host to enable GPU device access.
- GUI: `xhost +local:docker` is required to allow GUI applications to connect to the host X server; `manage.sh` handles this for you.

## Troubleshooting

- If you don't see your packages inside the container, verify they exist under `workspaces/ros2_ws/src` on the host.
- If IntelliSense misses headers, make sure `ROS_DISTRO` is set in the container (the devcontainer reads `${env:ROS_DISTRO}`) and run `colcon build` to populate `install/include` and `compile_commands.json`.
- To inspect mounts for a running container:

```bash
docker inspect --format '{{json .Mounts}}' ros_dev_${ROS_DISTRO} | jq
```

## Rebuilding the image

When you change `Dockerfile` or `docker-compose.yml` run:

```bash
./manage.sh recreate
```
